# 固定关卡（13500px）

## 规格

- 逻辑进度 0..13500，对应世界 `x = -6750..6750`。`map` 15000×1400，两侧各留 1200 余量给相机与转场；视口 1528×1146（窗口 1100×825、`cameraZoom = 0.72`）。
- **13 栋楼顶 + 7 个房顶小屋、12 条楼间空隙**。楼顶高度只取 5 档：`-208 / -170 / -130 / -90 / -48`，相邻最多差 130px（跳跃峰值 202px），所以地形是明确的台阶式起伏而不是缓慢漂移。
- **空隙 423~545px**：单跳极限 513px，因此 **12 条空隙里有 8 条必须二段跳**才过得去；二段跳（`vy=20`，空中共约 905px 可跨越）是关卡的核心操作。
- **房顶小屋**：贴在某栋楼顶上的窄高块（宽 170~260、比楼顶高 140~180px），它同时是碰撞体和美术——跳上去或跳过去，单跳勉强、二段跳轻松。出生台（`-7480..-6250`）和终点台（`5983..7450`）都是宽平台，保证开局和结算时脚下有地。
- 掉进楼间空隙就会坠落：`y < -420` 判定坠亡。空隙没有"坑底"，视觉上就是两栋楼之间的街谷。
- **炮塔**：3 座，立在第 4/9/11 栋楼顶（相对楼顶中点偏移 +170 / -170 / +150，避开上方的积分方阵）。炮管跟着玩家转，玩家进入画面且距离 < 1100px 才开火（约 0.9 秒一发）。炮弹速度 = 距离/18，约 0.36 秒到达，带尾焰，出屏 ±200px 回收。
- **受击与拆除**：被炮弹打中扣 25 血（8 帧冷却防叠扣）；玩家身体撞上炮塔则**炮塔炸毁**并同样扣 25 血。血量归零即死亡。
- **积分球**：白色圆形，5 个方阵（3×3 与 5×5 交替，格间距 46px）挂在第 4/5/9/10/11 栋楼顶上方 90~132px 处，吃到 +10 分。方阵位置由楼顶矩形算出来，且会避开房顶小屋、避开出生台与终点台——这三条都由 `scripts/test-level.py` 断言。
- 速度 14px/tick（50Hz ≈ 700px/s），纯跑完 13500px 约 19 秒；自动跳跃机器人实测 991 tick ≈ 19.8 秒。
- 地形不是泥土平台，而是**一栋栋高楼的楼顶**：每个碰撞块的上表面就是那栋楼的屋顶，立面往下延伸到画面外；空隙就是楼与楼之间的街谷，从空隙里能看到背景城市的楼群和雾。
- 关卡末端 `x=6750` 有粉色信标（旗+楼顶边线）作为终点。

## 代码

- `main.spx`：地形与顶障矩形表、距离/计时、相机、流程与转场。矩形表是碰撞与图形的唯一真源。
- `Player.spx`：宽 28、高 114 的脚底锚点 AABB。先按 `vx` 做水平扫掠（侧壁贴边、不自动爬台），再按 `vy` 做垂直跨越判落地，最后在上升段做顶障夹取。
- `Ground.svg`：由 `scripts/build-ground.py` 按上面的矩形表生成（屋顶护栏、立面窗格、霓虹边条、楼顶设备、悬挂楼板、终点信标）。**表直接解析自 `main.spx`**，没有第二份拷贝；改表后重跑脚本即可。
- `level-background.svg`：由 `scripts/build-background.py` 生成的 15000×1400 远景（黄昏天空 + 远/中/近三层城市 + 雾带），与 `map` 同尺寸。因为人物跑在楼顶，远景城市的楼顶整体压在可通行高度之下，从楼顶俯瞰下去。
- `Camera.setXYpos Player.xpos + 80 / cameraZoom, 0`：目标把人物放在视口水平 40% 处；引擎相机自带平滑，实测稳定在 42.7%（偏置 111px / 视口 1528px），运动中不是严格固定像素。

## 操作与测试

- `←`/`→` 移动，`↑`/空格跳跃、松开再按二段跳；`ESC` 暂停/继续，`Q` 暂停→主菜单，`R` 死亡/通关后重开，`M` 结算→主菜单。
- 到 12000px 触发通关结算；死亡或通关都会把舞台重置藏进黑罩之后（见 `docs/UI.md`）。
- `python3 scripts/test-level.py`：从 `main.spx` 解析几何表，校验结构（不重叠、覆盖关全长）、每条空隙/高差都在跳跃包线内、悬挂楼板高度合理（可达但不必然撞）、自动跳跃机器人能走完全程、相机 40% 目标、JSON/SVG 可解析。它不是引擎或输入的端到端测试。
- headless 仅验证编译与启动；视觉必须 GUI 验收：起点、坑洞、顶障撞头、二段跳、暂停、死亡/通关转场、终点结算。

## 当前边界

- 早期无限跑酷留下的 `Coin` / `Obstacle` / `HUDPanel` / `DebugBox` 类文件已删除，造型目录也不再保留。
- **纹理上限**：单张纹理边长上限 16384px，所以关卡长度不能超过约 15000（地形图 = 关卡长 + 两侧余量）。再长必须分片，而分片精灵如果靠 `clone` 摆第二片，克隆会被画到最上层把人物和菜单盖住——这条路已经踩过。
- **精灵类型数量有硬上限**：XGo classfile 每个精灵类都会把整套引擎 API 复制进自己的方法表，反射包装表的容量是 2560，超了会在启动时报 `cannot alloc method ... cap:2560`。所以粒子（起跳扬尘/落地烟/拖尾长条/白方块）全部合并在一个 `Fx` 精灵里，用造型区分行为。新增精灵类型前先确认还能构建。
- 平台都是自底部延伸的实心块，没有悬空平台；顶障是静态块，不会掉落。
- 关卡是固定数据驱动的，没有随机生成或程序化拼接。
